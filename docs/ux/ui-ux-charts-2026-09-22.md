# Chart and results source audit

Read-only review of `/Users/timrichardson/Documents/projects/personal/blog/rewire-contributions`, commit `fd7f12c`. No browser used, no product files changed. Read repository AGENTS.md. Inspected chart components, CSS, query validation, related tests, and archived release `2026-09-20-b2596bdf5206/catalogue.json.gz`. The generated `public/omics/catalogue.json` is absent locally, so numerical examples below come from that immutable archive rather than a live response.

## Prioritized findings

1. **P1 — Overview chart labels and values become unreadably small on mobile (verified implementation; calculated sizes, not a screenshot).** `components/catalogue/CatalogueCharts.tsx:15`, `:23`, `:30`, `:46`, `:62` put all typography in a 620-unit-wide SVG, rendered at 100% container width. At a 375px viewport, `.wrap` leaves 335px (`app/globals.css:704`): 12.5-unit labels become about 6.75px and 11-unit values become 5.94px. A fixed 164-unit right-aligned label endpoint also leaves no wrapping for long names such as “Virtual Cell Challenge 2026” or “PEtab benchmark collection”; likely clipping should be visually confirmed. Use HTML rows with normal-size wrapping labels and values, and scale only the bar track. On mobile place labels above bars, maintaining 14–16px text.

2. **P1 — Overview chart data has no equivalent accessible representation (verified markup).** `CatalogueCharts.tsx:29–36` marks the whole SVG `role="img"` and labels it only “Record count by kind”, “Record count by research area”, or “Evaluations reachable per benchmark”. There is no textual row summary, table, `<desc>`, or accessible links. SVG descendants are normally treated as a single image in the accessibility tree, so its generic accessible name does not convey the categories and counts. Provide a semantic list/table adjacent to the graphic or make HTML data rows the primary presentation. Benchmark comparison charts already do better: per-row accessible names and an expandable values table (`BenchmarkCharts.tsx:86`, `:238`).

3. **P2 — Zero and very small counts are drawn at the same nonzero length (verified bug).** `CatalogueCharts.tsx:39` uses `Math.max(2, value / max * plotW)`. The archived release includes PEtab with zero evaluations and NABench with 1,101; zero therefore receives a 2-unit bar, as would counts through 5. This contradicts the code's stated intent to make evidence gaps explicit (`:100–106`). Use zero width for zero, with a textual “No linked evaluations” indicator; use a separate small-value marker if necessary without representing it as a bar length.

4. **P2 — Coverage bars are ordered by a different variable than they display (verified inconsistency).** `scripts/omics/audit-benchmark-evidence.ts:17` sorts descending by metric-row count; `app/page.tsx:40–43` plots evaluation count. Thus scIB (69 evaluations, 821 results) appears above BEELINE (384 evaluations, 588 results) and ProteinBench (556 evaluations). The length pattern looks arbitrarily unsorted. Sort coverage rows by evaluations, label the plotted measure explicitly in visible text, and expose result-row count separately if useful.

5. **P2 — Comparison selector exposes raw records and does not scale to the released catalogue (verified content/control; redesign recommendation).** `BenchmarkCharts.tsx:284–287` puts title plus metric into a single native select. The archive has 95 choices for ProteinBench, 71 for BEELINE, and 43 for NABench. Seventy-one distinct panel titles contain raw JSON such as `{"reference_network":"Cell-type specific ChIP-Seq","gene_selection":"TFs+500"}`; many titles already end in the metric, which the control repeats. `.chartSelect` truncates long text (`database.module.css:453–464`). Provide readable titles, separate metric and protocol/dataset selectors, search for large choice sets, and show the selected scope clearly below. Keep source locators and internal IDs in evidence details.

6. **P2 — Large benchmark charts lose their numeric scale during scrolling (verified structure; design recommendation).** `BenchmarkCharts.tsx:55–62` renders the only axis above all rows; `database.module.css:496–503` assigns each row at least 24px for the SVG plus 18px margin, in addition to its label. Released panels contain up to 80 rows: the plotting portion alone exceeds 3,360px before labels, so lower rows are far from the axis. There are no common vertical grid lines, sticky scale, row limit, model search, or direct chart/data view switch. Use a compact dot plot or aligned bar table with a persistent/repeated scale and search; expose a full data view. Preserve source order by default and keep sorting within one compatible panel.

7. **P2 — Filtered empty results incorrectly claim that the release contains no evaluations (verified bug).** `Results.tsx:173–174` says “No evaluations linked in this release” whenever filtered `data.total` is zero. The service independently applies metric/origin/setup filters (`catalogue-query.ts:543–550`), while controls retain all initial facet choices (`Results.tsx:116`, `:134`, `:150`), so combinations with no matching rows can trigger this despite real evaluations. Distinguish genuinely empty records from “No results match these filters” and provide a clear-filters button.

8. **P2 — Result pagination loses location and backward navigation (verified control limitation).** `Results.tsx:322–340` only offers “First page” and “Next results”; no previous page, visible row range/page state, URL persistence, or focus move to the new content. A reader who goes past a result must restart and traverse again. `:84–87` groups after the API paginates individual metric rows (`catalogue-query.ts:551`), so evaluation groups can also continue across pages without an explicit continuation label. Show “Rows 26–50 of N”, add previous/history navigation, and preserve filter/page state in the URL. Consider group-aware pagination or a continuation indicator.

9. **P2 — An unsuccessful chart change leaves the selector naming one figure while another remains displayed (verified behavior with explicit warning).** `BenchmarkCharts.tsx:259–260`, `:270–277`, `:285–290` separate requested selection from loaded panel. The warning correctly says the previous figure is retained, but the selector remains on the failed requested comparison. This is especially easy to misread after scrolling below the alert. Keep requested/applied state explicit, restore the selector on failure, or show a persistent “Displaying [loaded comparison]” banner directly on the figure. Do not remove the last valid data without a clear replacement state.

10. **P3 — Overview describes every bar as a filter, but bars are static (verified wording/interaction mismatch).** `app/page.tsx:81` says “Every bar is a filter you can apply above”; `CatalogueCharts.tsx:37–68` renders only SVG text/rectangles without links or handlers. The sentence can mean manually using the controls above, but invites clicking the bars. Make the labels genuine links that apply the corresponding filter, or state explicitly that these are counts and direct the reader to the filters.

11. **P3 — Chart scales maximize each panel independently and lack reference-range context (design recommendation, not a data bug).** `BenchmarkCharts.tsx:48–52` always uses zero and the observed extremes. That keeps a zero baseline, including negative values, but a bounded score's maximum can look like a full-scale perfect result; switching panels silently changes scale. Use stable metric-specific domains where scientifically valid (e.g. known bounded measures), explicit axis label/unit, and reference marks only when justified by that metric/protocol. For close scores consider point plots with stated domains rather than cropping bar baselines. Preserve the existing “higher/lower is better” statement.

12. **P3 — Scientific qualifications appear after the full plot or in closed disclosure panels (design recommendation).** `BenchmarkCharts.tsx:224–246` puts the point-estimate/significance qualification below potentially 80 rows and hides scope caveats and uncertainty table by default. When an uncertainty interval is not supported by structured data, keep its printed value and do not invent error bars. Put a concise critical-scope/uncertainty sentence before the plot, leaving detailed provenance expandable. Current per-row origin labels, original printed values, source links, and unit/direction caption should be retained.

## What is already correct

- `services/omics/src/published-comparisons.ts:157–174` rejects nonfinite values and mismatched metric, unit, direction, protocol, or dataset. Lines 195–205 also reject mixed split/subset/population/aggregation. No evidence found that chart code pools incompatible metrics; keep this boundary during redesign.
- The gate deliberately permits equally missing comparison metadata, with caveats, rather than claiming independent reproducibility. Tests explicitly assert this (`tests/omics-published-comparisons.test.tsx:172`).
- Comparison chart values are release-backed; null numeric values are omitted from the plot with an omission count and retained in the table. Source order and row origin are preserved, and higher/lower direction is stated.
- Comparison value tables use caption, scoped header cells, and a keyboard-focusable scroll region. Result tables use scoped column and group headers, visible focus styling, and honest loading/error text.
- `./node_modules/.bin/vitest run tests/omics-published-comparisons.test.tsx` passed: **22/22 tests**. These cover grouping, provenance, null values and static rendering; they do not establish mobile readability or interactive selector/filter recovery. No dedicated CatalogueCharts test was found in the searched test directory.

## Recommended design direction

For the overview, replace the giant scalable SVG with semantic, responsive rows: readable benchmark links, exact evaluation counts, proportional bars, honest zero states, and a searchable/expandable list. Explain that counts measure catalogue coverage, not model performance or research quality. For scientific comparisons, use a compact labelled point/bar table with one metric and one protocol/dataset scope at a time, durable scale context, readable uncertainty, and immediate access to the underlying source table. Add a few targeted visual/interaction checks at 375px and desktop widths using actual long titles and an 80-row panel.
