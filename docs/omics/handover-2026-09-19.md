## How to add a benchmark's numbers

One extractor per paper in `scripts/omics/extract/`, plus one line in
`extractedBatches` in `scripts/omics/inputs.ts`. Everything else is shared.

- `extract/tables.ts` reads the artifact. It handles LaTeXML, JATS, plain HTML
  and PDF text layers, and knows about bold digits, small capitals a PDF split
  apart, scientific notation, and cells that hold two measurements.
- `extract/batch.ts` turns a parsed table into records and enforces the three
  rules every batch must obey.
- The extractor verifies the artifact's SHA-256 before reading a byte, and
  writes a receipt next to the batch. The release refuses a batch whose digest
  does not match its receipt, so a hand-edited jsonl fails the build.

```bash
npx tsx scripts/omics/extract/<name>.ts <artifact> [<pdf>]
npm run omics:release
npx tsx scripts/omics/audit-benchmark-evidence.ts
```

### The three rules, and why they exist

1. **A task reaches its benchmark only through a sourced claim.** The catalogue
   will not roll results up over an unevidenced edge, so each task carries a
   claim citing the row that says it belongs to the benchmark. Forget this and
   the benchmark page shows zero while the task pages show numbers.
2. **A cell with no number is not a result.** A dash means the method was not
   run. Writing a zero there invents a measurement.
3. **A figure compares one metric on one dataset.** Panels are per task. A mean
   over different metrics is not a score.

### Traps that cost time here

- **Do not use `kind: "model"`, `benchmark`, `dataset` or `baseline`.** Those
  are 1.0 kinds and the release requires every one of them to appear in the
  reviewed entity classification map, which is hash-locked behind an independent
  review. Use `method`, `configuration` or `dataset_subset`, which describe what
  a comparison table actually holds. `batch.ts` will not let you pick the others.
- **Tests that build from `currentCatalogueBase` must pass
  `{ entity_schema_version: "1.1" }`.** Without it the release builds at 1.0 and
  rejects the newer kinds.
- **Direction is not optional and not guessable.** Roughly a fifth of these
  metrics are errors where lower is better. Take it from the paper: ProteinBench
  and TDC print an arrow beside every metric, and TDC's arrows are cross-checked
  against the metric its Table 3 assigns each dataset.
- **Read the table, then its caption, never the reverse.** Matching the wrapper
  first breaks on nesting: a non-greedy match for the closing tag stops at the
  first inner one and returns a table with its last rows missing, which is worse
  than no table because it still parses.
- **Assert the row and column counts.** Every extractor does. A silently partial
  read is the failure mode that matters.

## How to add run instructions to a page

`scripts/omics/recipes/projects.ts` holds one entry per project: the repository,
the commit, the README's SHA-256, and the line ranges to quote.
`scripts/omics/recipes/build.ts` cuts those lines, emits the source records and
overlays, and rewrites the review receipt.

```bash
npx tsx scripts/omics/recipes/build.ts <directory of pinned READMEs>
```

Snippets are quoted by line range, never retyped, and the locator names the file,
the commit, the heading and the lines. The builder refuses a range that crosses
a code fence or contains no command; both caught real mistakes while the ranges
were being written. Nothing here is executed, so every instruction carries
`source_reviewed_not_executed`, which is what the schema requires before a page
may claim anything stronger.

Five projects publish no runnable command in their README and are deliberately
absent: FLIP, GENEB, Open Problems, TAPE and ProteinGym. An invented command
would be worse than an empty section.

## The runner

`rewirebench` runs four protocols: MFASS v2 (two ids), ProteinGym v1.3, the TDC
ADMET group and Genomic Benchmarks. A protocol exposes `prepare(source,
**options)` and `score(dataset, predictions)`, and is registered in
`sdk.PROTOCOLS`.

The bar is set by the existing modules: pin the upstream revision, transcribe
the metric from upstream's own evaluator with a line-level citation, assert the
canonical counts, and report coverage rather than hiding a partial run. The two
new protocols read what the upstream package wrote to disk and record its
digest, which is a weaker claim than MFASS makes and the honest one: the split
is a property of the copy you downloaded.

Where upstream is ambiguous, say so in the report rather than choosing quietly.
Genomic Benchmarks takes its integer class label from filesystem order, which
differs between machines, so the protocol sorts class names and records the
mapping; and the paper does not state which F1 averaging it used for its one
three-class dataset, so macro and weighted are both reported and neither is
presented as the paper's number.

## What is left

### Ten benchmarks with no numbers

`beeline`, `cafa`, `cami`, `capri`, `casp`, `flip2`,
`petab-benchmark-collection`, `plinder`, `scib`,
`virtual-cell-challenge-2026`.

A better parser will not fix any of them. Their pinned primary sources report
results in figures, in prose, or not at all, and the CAPRI page no longer
matches its pinned hash. Each needs a different artifact: a supplementary table,
a leaderboard export, an assessment site file. CASP does publish results tables
at predictioncenter.org, but they are unbalanced legacy HTML that the strict
reader refuses, and parsing z-scores out of malformed markup was not worth the
risk of publishing a wrong number.

### A decision for Tim: the export does not scale

The build prerenders 14,215 pages into 6.3 GB across 28,557 files. Firebase
Hosting caps a version at 40,000 files, so roughly one more batch of this size
breaches it.

About 10,000 of those pages are individual `result` and `evaluation` records.
They are rows, shown in full on their parent model, task and benchmark pages,
rather than documents anyone navigates to. Not prerendering them would remove
most of the weight. That changes what the site serves, so it is Tim's call and
has not been made.

Interim fixes already in place: the build heap is raised per job in both
workflows, and the Firestore import batches by bytes as well as document count.
Do not lower either.

### A flaky deploy probe

`scripts/check-live-catalogue.mjs` asserts the submissions endpoint returns 503.
Seconds after a functions deploy a cold start returned 500, which halted the run
before the website step and left the API on the new release while the site
served the old one. Re-running the failed jobs fixed it. The probe wants a retry
around that assertion.

## The standing rule

Never fabricate. Not a hash, not a command, not a metric direction, not a source
locator. If the paper does not say, the record says the paper does not say. Two
numbers in this work were wrong and both were caught by a check that existed for
that purpose: a fabricated commit hash typed as a placeholder, and a headline
evaluation count in PR #17's description, corrected in a comment on that PR.
