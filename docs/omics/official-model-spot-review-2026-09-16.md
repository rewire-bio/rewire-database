## Evidence-table quality consideration

The current profile component renders source links and locators beneath each value, so origins are accessible. However, several profiles reuse a broad source bundle for every fact. For example, the DNABERT-2 Architecture fact includes a checkpoint LICENSE among five sources, and Boltz-2 architecture, training and access fields share the same six-source bundle. This is not itself evidence that the claims are false, but the new field-level origin table should not imply that every listed artifact supports every clause.

Prefer the specific paper section/configuration for architecture, the model card or training Methods for training data, and the exact licence file for terms. Display artifact version and locator in addition to a friendly source name. Sources inherited only at record level should be labelled as record context rather than fact evidence. Preserve source warnings and the distinction between `unreported`, `unavailable` and `source_checked`.

## Scope and remaining quality gaps

The eight-model profiles’ strengths are conservative capabilities, such as accessible representations, released checkpoints or supported input types; they are not claims of universal superiority. That is scientifically preferable to adding unsourced performance praise. More task-specific comparative strengths would require explicit compatible evaluation evidence and are not a correction implied by this audit.

Some paragraphs still read as concatenated fact summaries. The RNA-FM correction addresses the one that is also stale. The remaining stylistic issue is lower priority than exposing precise evidence origins. The supplied diagrams accurately convey high-level flow; they are conceptual summaries, not full layer schematics. This audit did not retest their rendered mobile layout or reproduce any benchmark score.
