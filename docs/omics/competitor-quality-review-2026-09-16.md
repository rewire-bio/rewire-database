# Comparative quality review — 2026-09-16

The useful target is a catalogue that combines clear model explanations, independently verified facts and evaluation records that readers can audit. More entries, longer prose or a higher aggregate score do not establish better quality. The acceptance criteria below are proposed release requirements, not a claim that our current release already meets them.

## Scope and method

Inspected public first-party pages on **2026-09-16**: bio.rodeo’s leaderboard, methodology and two complete model overviews; ProteinGym’s official repository; an Open Problems task and safeguards; BEND’s official repository; and CELLxGENE Census documentation. These resources serve different purposes: discovery catalogue, executable benchmark and data infrastructure. The comparison is a targeted sample, not a site-wide error audit. Rendered text was inspected; authenticated features, every interactive tab and benchmark execution were not tested. ProteinGym’s website yielded no readable text through this retrieval tool, so observations below concern its official repository rather than its visual interface.

Competitor descriptions are evidence about their presentation only. They must not become the source for scientific facts in our catalogue. A candidate fact discovered there needs independent verification against its paper, supplement, official implementation, dataset or licence artifact.

## Quality acceptance rubric for our profiles

These are editorial and data-integrity requirements inferred from the comparison. They are not scores assigned to competitors.

| Priority | Requirement | Concrete acceptance check |
| --- | --- | --- |
| P0 | Independent origin for every factual claim | Every populated scientific field, factual summary and result resolves to an inspected primary artifact plus a section, table, figure, repository path/lines or dataset record. Competitor pages are discovery leads only. |
| P0 | Auditable source-origin table | Each claim-to-source row identifies record ID, field/claim, source ID, original URL, pinned version/commit/DOI revision, retrieval date, artifact SHA-256, locator and review status. Derived claims additionally identify inputs and transformation. Multiple sources remain separate rows. |
| P0 | Exact entity and version | Explicitly distinguish model family, checkpoint, wrapper, benchmark suite, concrete protocol and editorial task guide. Every result identifies its evaluated model and protocol version or displays the unresolved identity. No family-wide numbers copied from one checkpoint. |
| P0 | Comparable results only | A comparison requires matching dataset version/subset, split, target, metric definition/direction, allowed inputs, adaptation regime and aggregation. Display incompatible or unresolved results separately and explain the difference. |
| P0 | Honest missingness | No unfinished extraction is counted as researched completion. “Unreported” names the inspected source scope; “unavailable” identifies the access failure; “inapplicable” explains the entity’s scope. Missing facts never become zero, false or an assumed default. |
| P0 | Statistical precision | Identify SD, SE, confidence interval or other uncertainty exactly, including replicate/resampling unit and number when reported. Separate variation across targets, assays and random seeds. Preserve printed values and rounding. |
| P0 | Leakage evidence is specific | Describe the actual partition unit, temporal/homology exclusion and pretraining-overlap checks separately. A split, held-out label file or aggregation rule must not be described as proof of no leakage. Conflicting cutoffs remain visible. |
| P0 | Usable access and licence scope | Distinct evidence for code, weights and applicable service/output terms; distinguish repository metadata declarations from licence files. Access links identify the artifact or service they open. |
| P1 | Explanatory value | Every profile explains the question, inputs, outputs, computational approach, supported use, evidence-backed strengths and material limitations. A diagram clarifies the process when helpful; conceptual diagrams are labelled and cannot imply verified implementation detail. |
| P1 | Traceable result coverage | Show evaluated versus missing methods/datasets, failure or warning state, baseline roles, raw values and aggregation. Never silently rank a partial run as fully comparable. |
| P1 | Reader can investigate or correct | A profile links to concrete source evidence, downloadable structured records and relevant protocol/results; a correction route identifies the affected record. Release date and change history distinguish updates from original reports. |
| P1 | Discovery stays scientifically scoped | Search/filter by biological question, modality, organism, adaptation and access when supported. Popularity can aid discovery, but never establishes accuracy, reproducibility or suitability. |

A release may be fully researched while some primary sources omit details. Report **records reviewed, claims verified, scoped source omissions, inaccessible evidence and unresolved contradictions separately**. Coverage percentages must identify their denominator and must not treat “inapplicable” or a linked bibliography as verified scientific content. A superiority claim requires a repeatable comparison of the same sampled questions against this rubric; this document alone does not establish it.
